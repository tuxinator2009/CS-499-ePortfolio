Software Engineering and Design

The first enhancement to the Travlr Getaways application focuses on software architecture, maintainability, defensive programming, authentication, and separation of concerns.

Travlr Getaways was originally created for CS 465: Full Stack Development. The application combines an Express and Node.js backend, MongoDB persistence through Mongoose, an Angular administrative interface, server-rendered customer pages, RESTful API communication, and JSON Web Token authentication.

The original implementation successfully met the functional requirements of the course project, but the capstone code review identified several opportunities to improve the internal structure and security of the application.

Enhancement Overview

The primary goal of this enhancement was to replace a controller-centric backend design with a more clearly layered architecture.

Original Architecture

Route
  ↓
Controller
  ↓
Mongoose Model
  ↓
MongoDB

In the original application, controllers handled HTTP requests and responses while also directly performing database operations. This worked for a small project, but it increased coupling and placed multiple responsibilities in the same modules.

Enhanced Architecture

Route
  ↓
Controller
  ↓
Service
  ↓
Repository
  ↓
Mongoose Model
  ↓
MongoDB

The enhanced architecture separates HTTP handling, application rules, validation, and database access into distinct layers. This makes the application easier to understand, maintain, test, and extend.

Key Improvements

Layered Backend Architecture

Direct Mongoose queries were removed from the trip controllers and moved into a dedicated repository layer. Business rules and validation were moved into a service layer, while controllers now focus on HTTP request and response behavior.

JWT Authentication Middleware

Authentication logic was extracted into reusable middleware. The original implementation called next() outside the asynchronous JWT verification callback, which could allow request processing to continue before verification completed. The enhanced implementation continues only after successful token validation.

Angular Route Protection

Administrative Angular routes were protected with a route guard. The Express API remains the authoritative security boundary, while client-side route protection provides defense in depth and improves the user experience.

Improved Login Flow

The original Angular login process relied on a fixed three-second timer before checking whether authentication had completed. The enhanced version responds directly to the authentication observable, eliminating timing assumptions and improving reliability.

Error Handling and Validation

Consistent application errors were introduced, along with improved validation for incoming trip data and clearer handling of database and authentication failures.

Configurable Application Behavior

The hard-coded Angular development origin used for CORS was replaced with environment-based configuration, while preserving a localhost fallback for development.

Enhancement Narrative

Artifact Description

The artifact selected for this enhancement is the Travlr Getaways full-stack web application originally developed during CS 465: Full Stack Development. The application consists of a customer-facing website built with Express and Handlebars, a RESTful API developed with Express and Node.js, an Angular single-page application for administrative management, and a MongoDB database accessed through Mongoose. The application also includes JWT-based authentication for administrative functions such as adding and updating travel packages.

I selected this artifact because it represents one of the most technically complete projects I completed during the Computer Science program. Unlike projects focused on a single technology, Travlr Getaways integrates front-end development, back-end development, database management, authentication, and API communication into one cohesive application.

Justification for Inclusion

The original implementation successfully met the functional objectives of the CS 465 project, but reviewing the code revealed several opportunities to improve maintainability, modularity, and overall software quality.

The primary enhancement focused on software architecture. The original application followed a relatively direct flow in which controllers handled HTTP requests while also performing database operations through Mongoose. Although appropriate for a classroom project, this design tightly coupled multiple responsibilities within the controller layer.

To improve the design, I refactored the application into a layered architecture consisting of routes, controllers, services, repositories, and the underlying Mongoose models. Controllers now focus on HTTP request and response handling, business rules and validation are centralized in the service layer, and database interactions are isolated within the repository layer.

Additional improvements included extracting JWT authentication into reusable middleware, correcting the authentication flow so requests continue only after successful token verification, improving API error handling, and making CORS configuration more flexible.

On the Angular side, I implemented client-side route guards, improved JWT parsing and expiration handling, and redesigned the login workflow to eliminate timing-based navigation.

Course Outcome Alignment

This enhancement demonstrates progress toward the program outcome involving the use of well-founded computing practices and tools to implement solutions that deliver value. The layered architecture improves maintainability and establishes clearer boundaries for future development.

The enhancement also contributes strongly to the security outcome. Corrected JWT verification, defensive token handling, route protection, validation, and improved error handling strengthen the application's authentication boundary.

Clear module responsibilities, documentation, and architectural organization also support professional communication and collaborative development by making the application easier for another developer to understand and extend.

Reflection

Enhancing this artifact reinforced the importance of software architecture beyond simply producing working code. The original implementation satisfied its functional requirements, but revisiting it with additional experience revealed how clearer separation of responsibilities can make future development significantly easier.

One of the most valuable lessons from this enhancement was recognizing how separating application concerns simplifies later changes. Moving business logic into service modules and database access into repositories resulted in controllers that are easier to read and reason about.

Another important lesson involved asynchronous programming. The original authentication workflow attempted to predict when an API request would finish by using a fixed timer. Returning the authentication observable to the component instead allowed navigation to occur at the exact point authentication completed successfully.

A primary challenge was improving the architecture without unnecessarily breaking existing behavior. Because subsequent capstone enhancements would continue building upon the same application, I intentionally preserved existing API contracts where possible. This allowed the architecture to improve incrementally while maintaining compatibility with the Angular interface.

Overall, this enhancement transformed the application from a project designed primarily to satisfy coursework requirements into one that more closely resembles a professionally structured full-stack application.
