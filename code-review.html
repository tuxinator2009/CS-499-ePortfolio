Informal Code Review

Before beginning the capstone enhancements, I conducted an informal code review of the original Travlr Getaways full-stack application created in CS 465: Full Stack Development.

The purpose of the review was to evaluate the existing implementation, identify weaknesses and opportunities for improvement, and establish a practical enhancement plan in the three required areas of computer science: software engineering and design, algorithms and data structures, and databases.

The review also considers maintainability, defensive programming, authentication, authorization, input validation, error handling, testing, documentation, and security. The resulting findings became the foundation for the progressive enhancements presented throughout this ePortfolio.

Review Areas

Software Engineering & Design

The review examines the original route-to-controller architecture, controller responsibilities, authentication middleware, Angular route protection, error handling, and maintainability.

The planned enhancement introduces clearer separation among routes, controllers, services, repositories, and middleware while strengthening authentication and defensive programming.

View Software Engineering Enhancement

Algorithms & Data Structures

The review identifies the limitations of retrieving and displaying the complete trip collection without search, filtering, ranking, or sorting.

The planned enhancement introduces improved trip discovery using query processing, filtering, relevance scoring, deterministic sorting, and algorithmic trade-off analysis.

View Algorithms & Data Structures Enhancement

Databases

The review evaluates the original MongoDB data model, including trip lookup behavior, field types, indexes, user authentication data, and the absence of customer reservation data.

The planned enhancement expands the domain model with reservations, relationships, validation, indexing, aggregation reporting, ownership checks, and role-based authorization.

View Database Enhancement

Key Findings

  • Controllers were responsible for both HTTP behavior and direct database access, increasing coupling and reducing maintainability.
  • JWT middleware allowed request processing to continue before asynchronous token verification had completed.
  • Angular administrative routes were not protected by route guards.
  • Trip retrieval returned the complete collection without search, filtering, ranking, or sorting.
  • Price and duration values were stored as strings, limiting numeric processing.
  • The original data model did not support customer bookings, record ownership, historical booking information, or administrative reporting.
